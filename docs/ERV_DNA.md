# DNA ERV/TE insertion calling

The erv_dna pipeline (alias ervcaller) runs ERVcaller v1.4 on tumour and
matched-normal DNA independently. It complements the RNA STAR/Telescope
branch, which quantifies transcription at annotated reference loci.

ERVcaller detects **non-reference insertions**; it does not quantify
expression, reconstruct a complete tumour-specific ORF, or predict peptides.
An insertion absent from a normal VCF is not automatically somatic: coverage,
breakpoint uncertainty and missed calls must be evaluated. ERV expression
does not require a new DNA insertion. These outputs are not intersected with
Telescope counts or fed into pVACseq.

## Inputs and execution

Standalone mode uses the existing DNA samplesheet, one row per patient:

~~~csv
patient_id,tumor_bam,normal_bam
P001,/data/P001.tumor.bam,/data/P001.normal.bam
~~~

Both BAMs must be coordinate-sorted and indexed (.bam.bai or .bai).
Retain unmapped, discordant and soft-clipped reads. BAM contig names and
lengths are checked against the genome FASTA; use the exact alignment
reference, including decoys when present. This wrapper supports paired-end
DNA. WGS is the preferred starting point; WES has restricted insertion-site
coverage. ERVcaller's -d WGS is its DNA mode, not a declaration that every
input has whole-genome coverage.

~~~bash
nextflow run main.nf -profile gadi \
    --pipelines erv_dna \
    --dna_samplesheet dna_samples.csv \
    --ervcaller_container /scratch/jo11/singularity_images/ervcaller_1.4.sif \
    --genome_fasta /data/reference/genome.fa \
    --ervcaller_te_fasta /data/reference/erv_library.fa \
    --ervcaller_read_length 150 \
    --ervcaller_min_split 40 \
    --outdir results
~~~

Read length is required; adjust the example to the actual library. Mixed
read lengths require separate invocations. Set --ervcaller_bwa_mem true only
when all BAMs are BWA-MEM alignments. The default false lets ERVcaller realign
evidence from other aligners.

To reuse BAMs generated by the DNA branch, select
--pipelines dna_variant_calling,erv_dna. FASTQ and BAM input follow
the usual DNA preparation workflow (including its variant calling). Patients
with dna_vcf bypass that workflow and must also supply tumour/normal BAMs
and indices for ERVcaller. A VCF alone cannot supply insertion evidence.

For DNA insertion calls and RNA quantification together:

~~~bash
nextflow run main.nf -profile gadi \
    --pipelines erv_dna,erv \
    --erv_generate_peptides false \
    --dna_samplesheet dna_samples.csv \
    --rna_samplesheet rna_samples.csv \
    --ervcaller_container /scratch/jo11/singularity_images/ervcaller_1.4.sif \
    --genome_fasta /data/reference/genome.fa \
    --ervcaller_te_fasta /data/reference/erv_library.fa \
    --ervcaller_read_length 150 \
    --star_index_dir /data/reference/star_index \
    --erv_annotation_gtf /data/reference/telescope.gtf
~~~

RNA timepoints are arbitrary. Setting --erv_generate_peptides false ends the
RNA branch successfully after Telescope, skipping its existing peptide stub.
The default remains true to preserve the previous branch behaviour.

## Software and references

A local container is required on Gadi. There is no assumed public ERVcaller
image tag. Build the supplied recipe on a Linux Docker host:

~~~bash
docker build -t neoadjvax-ervcaller:1.4 -f containers/ervcaller/Dockerfile .
docker save -o ervcaller_1.4.tar neoadjvax-ervcaller:1.4
# Transfer this archive to a host with Singularity/Apptainer:
singularity build ervcaller_1.4.sif docker-archive://ervcaller_1.4.tar
~~~

Copy the SIF to Gadi and set --ervcaller_container to its absolute path.
The prefetch_containers.sh helper does not build or fetch this custom image.
Local Docker runs use -profile docker with
--ervcaller_container neoadjvax-ervcaller:1.4.

The recipe pins upstream commit
802dbf49ef61e722f16f84c0a6feb1283d8a360a and builds the **modified**
extractSoftclipped bundled with ERVcaller. It installs BWA, SAMtools, Perl,
R and Python. Ubuntu package versions are not locked; retain your built image
digest/SIF checksum when archiving a run. ERVcaller is CC BY-NC 4.0; TE
reference libraries have their own terms.

Select the TE FASTA explicitly. An ERV-focused library answers a different
question from a mixed Alu/LINE1/SVA/HERV library. All calls are retained and
labelled by the caller's INFOR field; no ERV-only name filter is applied.

By default, ERVCALLER_INDEX copies the two FASTAs into an isolated
ervcaller_refs work directory and builds their BWA and FASTA indices once
per run/cache. Source references are never modified. For repeated cohorts,
use --ervcaller_reference_dir with a prepared directory containing:

~~~text
genome.fa  genome.fa.amb  genome.fa.ann  genome.fa.bwt
genome.fa.pac  genome.fa.sa  genome.fa.fai
te.fa  te.fa.amb  te.fa.ann  te.fa.bwt
te.fa.pac  te.fa.sa  te.fa.fai
references.sha256  (optional checksum manifest)
~~~

This skips indexing and overrides both FASTA parameters for this branch.
Copy the directory from the completed index process work directory.
Container task paths must not contain whitespace or shell metacharacters:
upstream ERVcaller interpolates paths into shell commands internally.

## Outputs and interpretation

Each results/PATIENT/erv_dna/ROLE/results directory contains:

- PATIENT.ROLE.vcf: unmodified caller output, including low-quality calls.
- PATIENT.ROLE.evidence.tsv: TE identity, breakpoint status, read support,
  genotype and genotype quality, plus patient and tumour/normal labels.
- PATIENT.ROLE.status.json: counts, parameters, command, caller and
  reference checksums (FAI/TE, plus full FASTA hashes when the index step ran).
- PATIENT.ROLE.log: caller stdout and stderr.

The nested results directory is preserved by Nextflow publication.
Full intermediate files remain in the Nextflow work directory.

Positions in the evidence table are named caller_pos and remain unchanged.
The inspected v1.4 source subtracts one before writing VCF positions; validate
against known breakpoints before BED conversion or genomic intersections.
No automatic coordinate correction is applied to the original VCF.

The runner checks dependencies, BAM/reference compatibility and VCF structure,
and rejects common internal failures even when upstream returns exit code zero.
A valid header-only VCF is accepted. A **zero-byte VCF is rejected**, because
upstream can produce one on either no insertions or an internal failure; the
log must be investigated before treating it as a successful negative result.
These checks cannot establish biological accuracy or catch every upstream error.

Genotyping is enabled by default; --ervcaller_genotype false disables it.
Default minimum support is 3 and minimum split length is 20 bp. Upstream
recommends longer split segments, e.g. 40 bp, for 150 bp reads. The evidence
table applies no additional filtering. Review GQ, supporting reads, breakpoint
status, repeat context and normal coverage before prioritizing candidates.
Tumour purity and copy number affect interpretation of the diploid genotype.

## Verification

~~~bash
python3 -B -m unittest discover -s tests -v
nextflow -C tests/erv_dna/smoke.config run tests/erv_dna/smoke.nf -stub-run
~~~

Run from the repository root. The smoke fixture deliberately uses non-BAM
placeholders: it tests four patient/role tasks across two patients, not
biological accuracy. Never use it without -stub-run.
Before a cohort run, build the container and check one real paired sample.
